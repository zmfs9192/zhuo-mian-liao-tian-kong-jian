# 自测记录 2026-11-28-6（-15 轮：屏幕实时翻译，智能体视觉轮巡）

版本：2026-11-28-6（内部 2026.11.28-6）。本轮给工具箱加“屏幕实时翻译”：框选屏幕区域 → 只截选区 → 智能体一次完成认字 + 翻译（视觉调用）→ 浮窗分开展示原文与译文；翻译走翻译插件已有的智能体轮巡设置，不另起一套配置。只改 5 个热更新文件加发版相关文件（自测记录、README、update-manifest.json）与翻译插件页说明（`plugins-dev/translation/page.html`，插件源码，不走热更新清单）；凭据、数据文件、二进制包未进仓库；首次运行说明.txt 本轮不动。空间客户端本轮不动。

## 1. 实现位置

- 框选：`main.js`（`openScreenTranslateOverlay`，全屏半透明覆盖层，鼠标拖矩形、Esc 取消；选区窗口开在鼠标所在显示器上，`screenTranslateOverlayHtml`：选区外 `box-shadow` 压暗、框内透明露出原画面、顶部提示条、尺寸标签 tabular-nums）+ `preload.js`（`screenTranslateSelect/Cancel` 桥）+ `renderer/index.html`（菜单“屏幕翻译”，Lucide languages 图标，indigo 瓦片）+ `renderer/renderer.js`（`openMenuItem` 里 `screentranslate` 按动作处理，不切屏、不改菜单激活态；`startScreenTranslateFromUi`，菜单与设置页按钮共用）。
- 快捷键：`main.js`（`SCREEN_TRANSLATE_SHORTCUT = 'CommandOrControl+Alt+T'`，即 Windows 上 Ctrl+Alt+T；`registerScreenTranslateShortcut`，启动时注册，注册失败不拦启动、设置页显示注册状态；`before-quit` 里 `unregisterAll`）。
- 截图：`main.js`（`captureScreenRegion`：`desktopCapturer.getSources({types:['screen'], thumbnailSize: 4096×4096})` 取对应显示器的缩略图，按比例只裁选区，不传整屏大图；`screenTranslateCropRect` 纯函数换算并夹回缩略图内）。
- 视觉翻译：`main.js`（`buildScreenTranslateVisionMessages`：系统提示 + 用户文本 + `image_url` 图片块，提示词要求只返回 `{"original": ..., "translated": ...}` 一个 JSON 对象；`parseScreenTranslateResult`：JSON、围栏 JSON、非 JSON 兜底整段当译文，键名容错 original/source/text、translated/translation/target；`visionContentForAnthropic`：`agentChatCompletions` 的 Anthropic 分支把 `image_url` 的 data URL 转原生 `image` 内容块；`screenTranslateVisionCall`：网页令牌智能体不支持传图，直接判失败不调 `webChatSend`）。
- 视觉格式已接的服务商：OpenAI 兼容接口（DeepSeek、千问、豆包等 API 智能体）用 `image_url`；Anthropic 用原生 `image` 内容块；Gemini API 智能体在工具箱里走 OpenAI 兼容分支，同样用 `image_url`（工具箱没有 Gemini 原生 `inline_data` 路径，见 §4）。
- 轮巡复用：`main.js`（`getTranslationRoundRobinSettings`：按插件名找已安装的翻译插件（name 为“翻译”或 id 为 translation），再读它的 plugin-state；store 按安装 id 存，不是按 `translation.json` 文件名——任务书的说法已按实测纠正；`screenTranslateRoundRobin`：按轮巡顺序依次调用，失败顺延，成功或全部失败后都把 `nextIndex` 写回保存；间隔只在两次屏幕翻译之间生效，失败顺延不等待，避免一个不支持视觉的模型拖慢整轮；语言方向沿用插件的 from/to，auto = 中英互译自动识别）。
- 不支持视觉的模型：调用失败即当作一次轮巡失败顺延，不报错收场。实测会跳过的：纯文字模型（mock 里 `novision-model` 报 400 `model does not support images`，已顺延到下一个）；网页令牌智能体（不支持传图，直接判失败顺延）；未配 API 密钥的智能体（轮巡列表里不会出现——翻译插件只列已配密钥的智能体，主进程再判一次）。
- 浮窗：`main.js`（`openScreenTranslateResultWin`：无边框、始终置顶，440px 宽，位置由 `screenTranslateResultPos` 纯函数算——优先放选区右侧，右侧放不下放左侧，上下夹回工作区内；`sendToScreenTranslateResult`：加载中/完成/失败三种状态，`did-finish-load` 前发的补发一次；内容按 `render` 后 `scrollHeight` 自适应高度，夹在 200–640px；`screenTranslateResize` IPC 调窗高；`screenTranslateRetry` 用上次截图重翻；自动关闭：配置 `screenTranslate.autoClose` 为真时成功后 10 秒关，浮窗内任意 pointerdown 清除计时器）。浮窗页 `screenTranslateResultHtml`：原文/译文分段、复制译文（点后变“已复制”1.5 秒）、重新翻译、关闭；标题栏 `-webkit-app-region: drag` 拖动，按钮 `no-drag`；按设计系统做（内容驱动宽度、8pt 间距、60-30-10、1px 细边框、字阶、内联 SVG 关闭图标、加载骨架屏、深浅色跟随系统 `prefers-color-scheme`）。
- 未配轮巡时的明确提示：`getTranslationRoundRobinSettings` 返回 `code: 'no-plugin'`（还没装翻译插件）或 `'no-agents'`（没勾选智能体）+ 去处；`startScreenTranslate` 开浮窗直接显示原因，不静默、不自己编默认列表；设置页状态行与翻译插件页说明里也写了去处。
- 入口与设置：菜单“屏幕翻译”、快捷键 Ctrl+Alt+T、设置页通用页签“屏幕翻译”小节（开始框选翻译按钮、快捷键与注册状态、自动关闭勾选、语言方向沿用插件设置的说明；配置只存 `screenTranslate.autoClose`，不重复配智能体）；翻译插件页说明里加了一句（屏幕翻译走同一套轮巡设置）。
- 菜单项数：14 → 15 项（新增“屏幕翻译”）。两个旧断言同步改计数：`decouple20261128.menuCount14` → `menuCount15`（=== 15）、`designSystem20261128.menuTilesSvg14` → `menuTilesSvg15`（=== 15），只改计数，意图不变。

## 2. 自测（`screenTranslate20261128` 组，41 项全 true）

视觉调用本身用本机 mock 智能体端点测（127.0.0.1 临时端口），不调真实厂商接口；测完恢复插件、智能体与配置，不污染本机数据。

- 纯函数：`normalize`（归一化）、`clamp`/`clampNegative`（夹回显示区）、`cropRect`/`cropRectEdge`（1920×1080 显示器、2 倍缩略图的裁剪坐标与越界夹回）、`posRight`/`posLeft`/`posBottomClamped`（浮窗右/左/下沿夹回）。
- 视觉消息拼装：`visionOpenAi`（`image_url`，data URL 前缀对）、`visionAnthropic`（转原生 `image` 内容块，media_type image/png、base64 对）、`visionPromptHasFormat`（提示词含 `{"original"` 格式要求）。
- 结果解析：`parseJson`、`parseFenced`（围栏 JSON）、`parseFallback`（非 JSON 整段当译文）。
- 未配轮巡：`noPluginCode`（没装插件时 code no-plugin、提示含“翻译插件”）、`noAgentsCode`（装了插件不勾选时 code no-agents、提示含“勾选”）。
- 轮巡：`roundRobinFailover`（不支持视觉的 `novision-model` 报 400 后顺延到 `vision-model` 成功，原文 "Hello world"、译文“你好，世界”）、`roundRobinFailures`（失败列表里有 novision）、`roundRobinNextIndex`（成功后 nextIndex 写回保存）、`openAiImageSent`（mock 收到 `image_url`）、`anthropicVision`（Anthropic 智能体走 `/messages`，mock 收到原生 `image` 块，译文“你好”）。
- 快捷键：`shortcutRegistered`（`globalShortcut.isRegistered` 为真）、`shortcutStatus`（`screenTranslateStatus` 报告已注册）。
- 窗口：`overlayOpen`/`overlayBridge`（覆盖层打开、桥可用）/`overlayHint`（提示条含 Esc）/`overlayClosed`；`menuOpensOverlay`（点菜单项 → 覆盖层打开）；`resultOpen`/`resultLoadingShown`（浮窗打开、加载态）/`resultDoneShown`（原文与译文分开展示）/`resultFailNote`（有失败顺延时显示提示）/`resultClosed`。

## 4. 修中发现并修掉的问题

- 自测断言 bug（第一遍唯一新增 false）：`visionPromptHasFormat` 在 `msgs` 的字符串 content 里找 `{"original"`，但提示词实际在用户消息的 content 数组文本块里；已改查 `userContent` 的 text 块，第二遍 true。代码未动。
- 任务书说法纠正（两处，按实测为准）：① 翻译插件的轮巡设置不是按 `translation.json` 文件名存——`plugin-state` 按插件安装 id（随机 `localId()`）存文件，读设置要先按插件名（“翻译”）找已安装的插件，再读它的 store；② Gemini 没有原生 `inline_data` 路径——工具箱里 Gemini API 智能体走 OpenAI 兼容分支，视觉格式同样是 `image_url`，已在代码注释里写明。
