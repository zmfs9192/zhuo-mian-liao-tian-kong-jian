# 手机一键远程操作工具箱 — 方案（只出方案，不实施）

> 状态：方案稿，2026-11-28（工具箱 2026-11-28-4 随附）。目标是：手机像用 app 一样，
> 一键远程操作家里/办公室电脑上的桌面工具箱（看状态、发对话、开软件、查嗅探结果等），
> 不用在手机上装完整工具箱。
>
> 注意：2026-11-28-3 刚删了旧的远程服务器（19876 端口）与空间远程入口——那是给
> “空间小助手”用的旧代码，已彻底删掉，不要复用。本方案按全新的手机远程来设计。

## 1. 目标与边界

- 手机端：扫码或点链接打开一个轻量控制页（网页 app，可“添加到主屏幕”，不用上架应用商店），
  一键看到工具箱状态、一键操作。
- 电脑端：工具箱里新增“手机远程”开关与配对入口；默认关闭，不开就没有任何监听端口。
- 不做的事：手机上不跑完整工具箱、不在手机上存工具箱数据、不把账号密码与令牌发到手机上；
  远程操作只走工具箱主进程已有的能力（IPC/函数），不另起一套业务逻辑。
- 安全底线：默认拒绝所有远程连接；只有配对过的手机能连；敏感操作（删文件、卸载、发版、
  改代理、看令牌）默认不在手机端开放，或要二次确认。

## 2. 连接方式候选

| 方式 | 怎么做 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- |
| A. 局域网直连 | 工具箱在本机起一个只监听局域网的 HTTPS 服务（随机高位端口 + 自签证书）；手机与电脑连同一 Wi-Fi，扫码（二维码含 `https://局域网IP:端口/?token=…`）打开控制页 | 最简单、最快、不经过任何第三方服务器；断网也能用（只要 Wi-Fi 在） | 出了家/办公室就连不上；要处理 Windows 防火墙放行、IP 变化（DHCP）；自签证书手机浏览器会警告 | 家里、办公室同一 Wi-Fi 下用 |
| B. 内网穿透 / Tailscale | 电脑与手机都加入同一个 Tailscale（或同类 WireGuard 组网）虚拟局域网；工具箱服务只监听 Tailscale 网卡（100.x.x.x），手机用 Tailscale IP 访问，等同局域网直连 | 出门也能连（只要两边都在线）；不暴露公网端口；Tailscale 免费个人版够用；与 A 同一套服务代码，只是监听地址不同 | 两边都要装 Tailscale 并登录同一账号；首次配置多一步；依赖 Tailscale 服务可用 | 经常出门、想随时连的首选 |
| C. 云端中继 | 工具箱与手机都连到一个中继服务器（自建或第三方），通过 WebSocket 长连接转发指令与状态；手机扫码绑定后走中继 | 任何网络都能连，不用配网；手机端体验最像 app | 要有一台长期在线的中继服务器（成本与维护）；所有指令经过第三方，中继被攻破等于工具箱被攻破；延迟最高；要做端到端加密才安心 | 只有“随时随地都要连”且接受成本时才考虑 |

**推荐：A（局域网直连）先做，B（Tailscale）作为同一服务的第二监听地址一起上；C 暂不做。**

理由：A + B 共用同一套本地服务代码（只差监听地址），一次开发覆盖“在家”与“出门”两种场景；
都不经过第三方服务器，数据不出内网，最符合工具箱“数据只存本机”的原则；C 的服务器成本、
运维与信任问题都大，等 A/B 跑顺了、用户确实需要在任意网络下连时再评估。

## 3. 安全设计

- **配对码/令牌**：首次配对时工具箱显示 6 位配对码（或二维码），手机扫码后输入配对码；
  配对成功发一张长期令牌（随机 256 位，手机存浏览器本地存储，工具箱存 `data/phone-remote.json`），
  之后每次请求都带令牌；令牌可随时在工具箱里吊销（吊销后该手机立刻断开）。
- **仅本机授权**：配对必须在电脑前完成（工具箱界面点“允许配对”才会显示配对码，配对码 5 分钟过期）；
  远程不能发起配对、不能改配对设置。
- **操作范围限制**：手机端默认只开放只读与低危操作（看状态、看对话、发一条对话、开软件、
  看嗅探结果、收验证码）；高危操作（删除、卸载、清记录、发版推库、改代理、看/改令牌与密码、
  关机/重启）默认关闭，需要时在工具箱里逐项勾选才放开，且每次执行要手机端二次确认。
- **传输**：局域网内也走 HTTPS（工具箱启动时生成自签证书，配对时把证书指纹一起给手机校验，
  防中间人）；令牌只放请求头，不放 URL（二维码里的 token 只用于首次配对握手，握手完即废弃）。
- **防爆破**：配对码 5 分钟过期、错 5 次锁定 10 分钟；令牌连续 10 次无效直接吊销并记日志。
- **日志与可见性**：所有远程操作记一条日志（时间、手机名、操作、结果），工具箱“手机远程”页可见；
  工具箱托盘图标在有手机连接时变色，电脑前一眼能看到有人在远程操作。

## 4. 手机端形态

- **扫码打开的网页 app（推荐，不做原生 app）**：手机扫工具箱里的二维码 → 打开控制页
  （PWA：可“添加到主屏幕”，有图标、全屏、离线壳）；界面只保留手机上常用的操作，
  大按钮、单列布局，与桌面端完全不同的精简版。
- 为什么不用原生 app：不用上架商店、不用等审核、改版面跟着工具箱热更新走；扫码即用，
  换手机重新扫码配对就行。
- 首屏：一键操作区（当前状态、常用智能体发对话、打开浏览器/播放器、今日嗅探摘要、
  待收验证码）；次屏：对话列表、文件快览、工具箱开关（嗅探开关、代理模式只读显示）。

## 5. 工具箱端要新增的能力清单

1. 本地 HTTPS 服务模块（`main.js` 新段）：只在“手机远程”开启时监听；
   监听地址：局域网 IP（A）与 Tailscale IP（B，有则监听）；端口随机高位、启动时生成、
   记入 `data/phone-remote.json`；自签证书启动时生成、指纹展示。
2. 配对与令牌管理：配对码生成/校验/过期、令牌签发/吊销、已配对手机列表（手机名、配对时间、
   上次连接、操作范围），存在本机 `data/phone-remote.json`（令牌按凭据处理，绝不进仓库）。
3. 手机远程设置页（设置子页）：开关、配对码/二维码展示、已配对手机管理、操作范围勾选、
   连接日志查看。
4. 手机 API（HTTP + JSON，只暴露白名单）：状态查询、对话列表/发送、打开软件/浏览器、
   嗅探摘要、接码记录查询、开关嗅探；高危操作另设单独接口且默认关闭。
5. 二维码生成：配对二维码（`https://<IP>:<端口>/?pair=…`，一次性）与控制页二维码；
   用现有依赖或轻量纯 JS 生成，不引入重型库。
6. 远程操作日志：记入工具箱日志体系，手机远程页可见，托盘图标状态联动。
7. 自测分组：配对流程（码过期、错码锁定）、令牌校验（无效吊销）、操作范围（高危默认拒绝）、
   服务未开启时端口不监听；真机验证：同一 Wi-Fi 扫码连接、Tailscale 出门连接。

## 6. 需要用户定的选择

1. **连接方式**：A（局域网直连）先做，还是 A + B（加 Tailscale）一起做？C（云端中继）要不要排进以后？
2. **手机端开放的操作范围**：默认只读 + 发对话 + 开软件够不够？删除/卸载/发版这些高危操作要不要在手机上开？
3. **配对方式**：扫码 + 6 位配对码够不够，还是要再加手机端手势/指纹确认？
4. **Tailscale**：如果选 B，电脑与手机用谁的 Tailscale 账号组网（用户自己的免费账号即可）？
5. **手机控制页要不要“添加到主屏幕”图标与名字**：名字就叫“工具箱远程”可以吗？

## 7. 工作量与顺序（估算，不实施）

1. 本地 HTTPS 服务 + 配对/令牌（约 1 轮）。
2. 手机 API 白名单 + 设置页 + 二维码（约 1 轮）。
3. 手机控制页（PWA 精简版）+ 自测 + 真机验证（约 1 轮）。
4. Tailscale 监听（B）是第 1 步的扩展，约半轮；云端中继（C）另立方案，不在本轮。
