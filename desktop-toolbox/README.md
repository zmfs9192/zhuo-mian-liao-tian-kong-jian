## 工具管理：四点怎么做到

1. **搜索未安装的商店应用**：「发现软件」搜关键词时，winget 默认源和微软商店源（msstore）各搜一次、按 ID 去重，未装的结果直接点「安装」。
2. **真的更新**：「可更新」页点「更新」或「全部更新」跑 `winget upgrade` / `upgrade --all`；点单个更新时记下旧版本，完成后自动刷新已安装清单并核对，提示「旧版本 → 新版本，已在已安装里核对」；已安装里找不到时如实提示再刷新一次。
3. **GitHub 登录并搜索仓库**：工具管理 → 可更新 → GitHub 页，先粘贴个人访问令牌（Personal Access Token）点「登录」。令牌只存在本机 `config.json` 里，不写进代码、不上传；登录后搜仓库（按星数排）、看 Releases；Release 里有 exe / msi 安装包的点「安装」下载并启动安装程序，装完后工具箱会在 8 秒后刷新一次已安装清单核对（按仓库名找）。
   - 建令牌：GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)，搜公开仓库不勾权限也能用；要装私有仓库的 Release 再按需加权限。
4. **安装后在已安装中显示**：winget 安装 / 更新任务完成时自动刷新已安装清单；GitHub 安装包启动后，工具箱 8 秒后刷新一次核对并提示。个别 exe 安装包不在 winget 清单里时，提示会如实说没找到、请再刷新一次。

## 必备环境与依赖（v1.2.0）

- **必备环境**：工具管理 → 可更新 → 环境与依赖（最后一页）有「必备环境」卡片，点「检查必备环境」会查 winget、.NET 桌面运行库 8、VC++ 2015-2022 运行库 x64、Python 3、Node.js LTS；缺的点「一键装齐缺的」用 winget 装。winget 本身缺了装不了（没有 winget 就没法用 winget 装东西），会明确提示去微软商店装「应用安装程序」。
- **装软件前查依赖**：点「安装」时先查依赖再确认。winget 包查清单里的 Dependencies；GitHub 安装包查 Release 说明里提到的依赖（.NET / VC++ / Python / Node）。缺依赖先列出来，点「依赖和本体一起装」会先装依赖再装本体；点「只装本体」会跳过依赖；点「取消」不装。
- **装完核对依赖**：装完自动刷新已安装清单，本体和依赖都要在里面核对到；GitHub 安装包是外部安装向导，工具箱 8 秒后刷新一次核对并提示。
- **依赖冲突**：已装版本低于要求版本时，安装前明确提示冲突原因和处理办法（升级依赖 / 并存 / 跳过）。VC++ 各版本累计、.NET 大版本可并存，一般不冲突，界面上会写明。
- **如实说明的边界**：winget 清单经常不声明依赖，Release 说明是自由文本——没声明 / 没写清楚的依赖，工具箱会说「无法自动检测」，不假装已检测；要求版本没写明的，只能报「未知，按本体要求为准」。
