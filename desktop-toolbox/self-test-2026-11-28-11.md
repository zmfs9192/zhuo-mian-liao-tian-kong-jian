## 1. 实现位置

### 第 1 项 — 嗅探系统代理模式崩溃后无启动清理，全系统断网（P1）

- 根因：`sniffProxyResetSystemSync()`（`main.js:6610`）只接在 `before-quit`；嗅探系统模式把 Windows 系统代理写成 `127.0.0.1:<随机端口>`，状态只在内存里（`sniffProxyState`），恢复点 `sniff-prev-proxy.json` 落盘但启动时没人读。工具箱在该模式下崩溃或被任务管理器杀掉，系统代理一直指向已不存在的监听，全系统上不了网。
- 修法：启动时调一次 `sniffProxyResetSystemSync()`，与 Pioneer 的 `pioneerCleanupStaleSystemProxy()` 对齐（`main.js` 启动段）。
- 自测组 `sniffStartupCleanup20261128`（函数存在、启动接线、Linux 下空操作不抛错、命令形状）。

### 第 2 项 — Pioneer 出口验证失败后没有恢复路径（P1）

- 根因：`pioneerConnect` 里出口验证失败时 `connected=false`、`tunnelRunning=true`、浏览器代理复位回直连，注释写“方便点‘检测出口 IP’重试”，但 Pioneer 页根本没有出口 IP 重测按钮；“IP 纯净度检测”重跑 `pioneerFetchExitIp`，即使通了也不把 `connected` 翻回 true、不重接浏览器代理。一次验证失败后隧道空转，唯一恢复办法是断开重连。
- 修法（取干净的那个：加独立动作）：新增 `pioneerReverify()`（`main.js`，在 `pioneerDisconnect` 之后）——重跑 `pioneerFetchExitIp`，成功翻 `connected=true` + 重接浏览器代理 + 清 streak，失败计两连击（第 2 次连续失败才复位）；新增 IPC `pioneer-reverify` + preload 桥 `pioneerReverify`；Pioneer 卡片新增 `#pioneer-reverify` 按钮“重新验证并恢复代理”，仅当 `tunnelRunning && !connected` 时显示（`renderPioneer` 里切）；`pioneerPublic` 补 `tunnelRunning` 与 `selectedCountryId`。
- 自测组 `pioneerReverify20261128`（无隧道拒绝、成功翻状态、首败不复位、次败复位并清 streak、按钮显隐）。

### 第 3 项 — Trojan 本地监听 SOCKS5 握手分包就掐连接（P2）

- 根因：`main.js:7126-7129`：`if (first.length < greetingLen) { client.destroy(); return; }`。HTTP 分支会累积等 `\r\n\r\n`，SOCKS5 分支第一段不够长就直接销毁。智能模式 PAC 返回的正是 SOCKS5 `127.0.0.1:19352`，这条路径是活的；回环上分包少见但真实存在（负载高时），表现为偶发页面打不开。
- 修法：问候与请求都先累积再解析（新增 `requestLen()` helper，按 atyp 1/3/4 算完整请求长度；`handleGreeting`/`onGreet` 上限 258 字节、`onReq` 上限 512 字节）。
- 自测组 `socks5Split20261128`（分包问候回 `[5,0]`、整包问候、分包请求回 `[5,0]` 应答——沙盒 MITM 出口代理会拖慢上游连接，测请求解析时临时清掉 `HTTP_PROXY/HTTPS_PROXY` 环境变量、测完恢复）。

### 第 4 项 — pioneerVerifyFailStreak 跨断开不断（P2）

- 根因：计数器只在验证成功时清零（`main.js:7276`）和自测里清零，`pioneerDisconnect`/`pioneerStopTunnel` 都不碰它。上轮残留的 `streak=1` 会带进下一次连接，之后一次瞬时失败就直接触发复位。
- 修法：`pioneerStopTunnel` 开头 `pioneerVerifyFailStreak = 0;`（断开与连接开始都覆盖，因为 `pioneerStartTunnel` 先调 `pioneerStopTunnel`）。
- 自测组 `failStreakReset20261128`。

### 第 11 项 — 数据嗅探完全无用（用户 2026-11-28 18:17，先诊断再动手）

- 诊断方法：本地 mock 页实测（`/tmp/sniff-mock.mjs`：全新 profile 的 Electron + CDP，mock HTTP 服务发图片/视频 mp4/m3u8/JSON/带 Cookie 的请求/种子文件/磁链链接）。
- 诊断结论（实测）：**引擎本身能抓**——嗅探开着时 mock 页 5 条全进池：img.jpg（image）、video.mp4（video）、play.m3u8（live）、Cookie 请求头、sessionid（Set-Cookie）；请求日志 7 条（含 `/file.torrent` 当“接口”）。抓不到的根因是三处，不是引擎没挂上：
  - (1) **换页就清池**：`onSniffPageChange` 每次 `did-navigate` 都 `clearSniffPool()`，且历史快照只在换站时存。登录流程必然导航（多半同站），登录页刚抓到的凭证/媒体一跳转就全丢，同站连快照都没有——实测：切到同站 `/home` 后池子从 5 条剩 1 条（仅新页重扫存储得到的 Cookie），历史 0 条。这就是“网页账号登录了也啥都抓不到”的机制。
  - (2) **面板默认钉在“其他软件”页签**：`sniffActiveTab` 在空池渲染时被钉在常驻控制页签 `proxy`（它永远在列表里，旧的“当前页签不在列表里才重置”永远触发不了），之后抓到东西也不切走——用户打开面板看到的是本地代理说明，不是抓到的视频。实测：面板默认显示 proxy 内容，视频行藏在视频页签后面。
  - (3) **开关默认关**：`config.sniffEnabled` 默认 false，没开过就一条都抓不到（开关在浏览器页的视频/嗅探卡片上）。本轮不改默认（嗅探默认关是隐私立场），只在汇总里说明。
- 视频链核实：抓到就能下——视频行有“下载”按钮（`sniffMediaRow`，`videoStartDownload` → `videoDownload` IPC）；链上唯一的门是视频引擎未装（实测 IPC 返回“视频引擎未安装：点下载时会问你要不要一键安装 yt-dlp”，点下载时弹一键安装，装好自动重下）。预览按钮（mp4 等）与 m3u8 只给下载不给预览（Chromium 原生播不了 HLS/DASH）均正常。本轮视频链本身不动，修的是让条目可见（下面两点）。
- 修法：
  - 同站导航不清池（`onSniffPageChange`）：换站才清池并存快照；同站导航（登录跳转、站内翻页）保留池子，每条带来源页地址；关嗅探时显式清池（`setSniffEnabled(false)` 调 `clearSniffPool()`，否则“关后换页”不再顺带清池、旧内容会赖着不走，自测 `toggleOffNoNewEntries` 的语义也靠它）。自测组 `sniffPoolSurvivesLogin20261128`（同站保留 2 条、换站清 0、默认页签切到 video、视频行有下载按钮、用户手动选过 proxy 后保持）。
  - 面板默认页签（`renderSniffPanel`）：用户没手动点过页签时，默认选中第一个有内容的页签（proxy 除外）；手动点过后保持选择（新增 `sniffTabUserPicked` 标志，页签点击时置 true）。
  - 种子/磁力（诚实范围）：`.torrent` 响应进池——`main.js` 新增 `isSniffTorrentResponse`（`.torrent` 扩展名或 `application/x-bittorrent`），`onHeadersReceived` 里发 `browser-media-found`（category `torrent`），请求日志类型加“种子”；页面里的磁链与种子链接由页面扫描发现——`SNIFF_STORAGE_SCAN_SCRIPT` 末尾扫 `a[href]`（磁链进池 type `magnet`、种子链接进池 type `torrent`，每次页面加载与手动“重新扫描”时扫，SPA 后加的链接等下次扫描或换页时再扫）；面板新增“种子/磁力”页签（`SNIFF_CATEGORIES` + 媒体页签列表 + `sniffCategoryOfUrl`）；行按钮：种子文件“下载种子文件”（新 IPC `sniff-download-file`，普通下载保存到默认下载目录）+“复制链接”，磁链“复制磁链”（复用 `copy-text`）+“系统打开”（新 IPC `sniff-open-magnet`，只接受 `magnet:?xt=urn:btih:`，交给本机已装的 BT 客户端，没装时系统提示选择打开方式）。**工具箱里没有 BT 客户端，不提供“下载 BT 内容”的假入口。**新增 preload 桥 `sniffDownloadFile`/`sniffOpenMagnet`。自测组 `sniffTorrent20261128`（分类器、真下载字节比对、磁链打开非法输入被拒、页面扫描找到磁链与种子、面板三按钮）。
  - 本轮修掉的真 bug：模板字符串反斜杠 bug——`SNIFF_STORAGE_SCAN_SCRIPT` 是模板字符串，磁链正则里的 `\?` 写单份会被模板解析吃掉（`?` 变成“:可选”量词），`magnet:?xt=...` 再也匹配不上；自测 run 2 的 `scanFoundMagnet` 失败就是它（同页孤立探针能过、整段脚本里过不了，定位靠在 webview 里直接跑扫描脚本 + 逐段隔离）。已改成双份 `\\?`（`.torrent` 的 `\.` 同理改 `\\.`），并在代码里留注释防再犯。另：mock 探针的 `app.kill('SIGKILL')` 只杀掉 electron 的 cli.js、electron 本体变孤儿进程残留（残留进程占着 Ctrl+Alt+T，导致 run 2 的 `screenTranslate` 两项失败），探针改 `detached: true` + `process.kill(-pid, 'SIGKILL')`，自测前清掉残留进程。
