### 1. 工具箱内置一键发布（版本 +1 并发布到仓库）

- 设置 → 更新子页工具栏新增「发布新版本（版本 +1）」按钮
  （`#update-publish-new`，`renderer/index.html`、
  `renderer/renderer.js` 的 `initUpdateButtons` /
  `onPublishNewVersion`），与原有 Contents API 发布按钮并列。
- 主进程 `publishNewVersion(opts)`（`main.js`，在原 `publishLocal`
  之后）：按 publish.js 的版本规则算下一版（日期固定、最后一位 +1），
  依次检查 git 已安装 → 在 git 仓库里 → 在 main 分支 → 已登录
  GitHub（有令牌）→ 磁盘两处版本号一致；再精确 `git add` 白名单
  （5 个热更新文件 + `package.json` + `update-manifest.json` +
  `README.md` + 本版自测记录），提交后用已存令牌推到仓库。
  失败时先还原 package.json / main.js / 清单快照再报原因；推送
  失败只报本地提交号与手动 `git push origin main`，不回滚已提交内容。
- 令牌绝不进日志、界面或提交内容：推送用一次性 askpass 临时文件
  （Windows 写 `.cmd`、其余写 `.sh` 700 权限，`GIT_ASKPASS` +
  `GIT_TERMINAL_PROMPT=0`，令牌不在 argv/env/日志里，用完即删）；
  推送目标写死 `https://github.com/zmfs9192/zhuo-mian-liao-tian-kong-jian.git`
  的 `HEAD:main`；提交身份先用仓库 git 配置，没有时用令牌查到的
  GitHub 登录名拼 `noreply` 邮箱。
- 没装 git、不是仓库副本、不在 main 分支、没登录 GitHub、没令牌时
  各有明确报错与去处（没令牌指去工具管理「工具来源」登录；没 git
  或不是仓库副本指去用 Contents API 发布按钮），不假装成功。
  正在运行的进程仍拿旧内存版本号，成功提示会写明重启后才生效。
- `runCmd` 加可选 `opts`（`{cwd, env}`）供 git 调用；IPC
  `publish-new-version`，`preload.js` 暴露 `publishNewVersion`；
  `dryRun` 模式只算版本与文件清单，不写任何东西。
- 自测分组 `publishNewVersion20261127`（11 项，全过）：版本 +1
  计算（`2026.11.27-10` → `2026.11.27-11`，非法格式回 null）、
  按钮存在、无令牌时明确报错且 package.json 与 git 状态都不变、
  dry-run（假令牌）算出下一版与白名单文件且不写任何东西、真推
  （本地 bare 仓库 + 假令牌）askpass 推完即删、结果里不含令牌。

### 3. 数据嗅探统一引擎（原 3 项 + 登录态 + 整合 + 5 项缺口）

不再是几套分开的嗅探，改成一套统一引擎（`main.js` 统一嗅探段、
`renderer/renderer.js` 嗅探段重写、`preload.js` 补桥接）：

- 一个总开关（现有 `sniffEnabled`）：开时给每个浏览器分区挂一套
  webRequest 监听，关时全摘掉，不重复叠加（`installSniffHooks` /
  `removeSniffHooks` / `refreshSniffHooks`，`set-config` 里刷新）。
- 一次分类（`sniffCategoryOf`，URL 后缀 + Content-Type + 大小多信号）：
  视频 / 直播流 / 音频 / 图片 / 文档 / 其他；另有登录态
  （Cookie / 本地存储 / 请求头令牌 / 响应体令牌）、流式消息、
  页面数据。噪声过滤（信标、埋点、1x1、spacer 等），小图不过线
  （实时抓图 50 KB 起，页面分析不限）；同一条请求只进池一次
  （主进程 `browserMediaSeen` + 渲染层 `upsertSniffItem` 去重，
  值没变不重复报，值变了才更新并高亮）。
- 一个结果池（`sniffItems`，上限 200 条）与一个嗅探框，按类别分组
  显示、每组带计数；条目只显示已知的信息（类型、大小、清晰度 /
  码率，有才显示，没有不编）。`.ts` 分片按 host + 目录折成
  「HLS 分片 ×N」。
- 登录态多层抓（只抓当前所在站点）：webRequest 请求头 / 响应头
  （Cookie、Set-Cookie、Authorization，同站才收）、`session.cookies`
  读该站 cookie、登录后读 localStorage / sessionStorage /
  IndexedDB（尽力，最多 3 库 3 表 20 行，2 秒超时）、响应体扫
  token 字段（`access_token`、`token`、`refresh_token`、`session`、
  `sid` 等）与类令牌串（JWT `eyJ…`、长 hex/base64、Bearer）；重点盯
  登录 / sso / oauth / token / refresh 类认证接口与域名；登录跳转
  后复核一次存储变化。嗅探框分组：Cookie、本地存储、请求头令牌、
  响应体令牌，每条写来源网址、名字、过期时间，值只显示前后几位
  打码，点一下才复制完整值；令牌绝不写日志与任何上报。
- 整合：实时媒体嗅探（`onBeforeRequest` → `browser-media-found`）、
  粘贴网址分析（`video-sniff` 后端留着，共用同一套分类与结果格式，
  「分析当前页面」按钮进同一个池；界面入口仍按 -10 不恢复粘贴框）、
  登录检测（`browserLoginCheck` 读到的 cookie 并进 Cookie 类别）
  全进同一个池与同一个嗅探框。`main.js:7593` 的 `sniff-auth-cookies`
  IPC 原来调的 `sniffAuthCookies` 全仓库无定义、调了就抛错，现由
  统一引擎实现（同站 cookie，坏参数回 `{ok:false}` 不抛错）。
- 5 项缺口全并进统一池与嗅探框分组：
  (1) WebSocket 与 SSE 流式嗅探——页面钩子补 `fetch` / `XHR` /
  `WebSocket` / `EventSource`（`webview.executeJavaScript` 注入，
  不用调试协议、不弹调试横条），聊天类流式回答归类为「流式消息」，
  只记文本摘要（前 200 字）与条数，不无限制存全文；
  (2) 全量请求日志——HAR 式，记方法、地址、状态码、大小、耗时、
  类型，上限 500 条滚动，只在嗅探开启时记，列表可按类型 / 域名筛，
  点一条取完整请求头响应头（只放主进程内存，按需取，Cookie /
  Authorization / Set-Cookie / token 头打码显示）；
  (3) 嗅探历史保存——结果落盘本机 `sniff-history.json`（按站点 /
  时间查、能删），换页面不丢，令牌类值打码保存、只在本机；
  (4) API 接口清单——从请求日志自动归纳，按域名分组、去重、带调用
  次数，数字 / UUID / 长 hex 路径段归一成 `{id}`；
  (5) 页面内嵌数据——系统化抓 `__NEXT_DATA__`、页面 JSON 状态、JS
  全局变量里的配置与地址（复用 `videoSniff` 已有的 JSON 键提取并
  扩展），归类为「页面数据」。
- 自测里修掉的两个真问题（见「自测过程」）：换页清请求日志时误删
  刚完成的主文档条目；`sniffReqLogType` 把 Electron 驼峰
  `mainFrame` 当成下划线 `main_frame` 比对，主文档一直被归成「其他」。

  除下面一项已知波动。
- 唯一与 -10 最后一遍不同的项：`mailtmFetch.ok`（true → false）。
  不是 -11 改动引起的：-11 没动这段代码；它在 -10 的两遍里本身就
  一过一不过；本轮 7 遍全部报「Mail.tm 取不到域名列表（网络不通或
  服务不可用）」，且沙盒里 `curl https://api.mail.tm/domains` 与
  `curl https://api.github.com` 都回 403（出口代理拦）。属沙盒网络
  限制下的已知波动项，不是回归。
- 自测过程（每遍都如实记）：
  - 第 1 遍：460 项，409 true / 51 false。统一嗅探组在
    `tinyImageExcluded` 后抛错（`Cannot read properties of undefined
    (reading 'includes')`）：登录态 / 页面数据条目没有 `url` 字段，
    测试的 `pool()` 助手直接 `x.url.includes`。另 `hookedDefaultPartition`
    false：统一引擎「关闭摘监听」后，开关关着时默认分区本来就不挂监听，
    旧分组在开启前读分区状态的期望已不成立。
  - 修：`pool()` 里 `url` 兜底为空串（`bigImageSize` 的 js 表达式同样
    兜底）；旧分组把 `hookedDefaultPartition` 的读取挪到
    `setSniffEnabled(true)` 之后（开启后核对已挂上）。
  - 第 2 遍：统一嗅探组登录页之后全挂（请求日志里连 login.html 都没有）。
    根因是测试用主窗口 `document` 去点 webview 里的 `#do-login` /
    读 `window.__wsCount` / `__toolboxSniffHooked`，访客页里的东西主窗口
    根本没有。修：测试加 `wvJs`（经 `#toolbox-webview` 的
    `executeJavaScript` 进访客页执行），并记录诊断字段。
  - 第 3 遍：除 3 项外全过。`reqLogHasPage` false：请求日志只有 POST
    一条，主文档条目被换页清空误删（`onCompleted` 可能先于
    `did-navigate` 到达）；`sseStreamFound` false：测试点订阅按钮时
    页面钩子还没注入完；`reqDetailShown` false：待查。
  - 修（产品）：`onSniffPageChange` 换页时只清旧页条目，url 等于新页
    地址的主文档条目保留；测试里 SSE 点击前先等
    `window.__toolboxSniffHooked === true`，详情检查改等详情文本出现
    （最多 6 秒）并先确认面板已打开。
  - 第 4 遍：SSE 过了；`reqLogHasPage` 仍 false，但日志里已有
    `GET login.html` 条目——只是类型是「其他」不是「页面」；
    `reqDetailShown` 仍 false，诊断：行 2 条、详情元素 1 个、
    `sniffReqDetailId` 已设，面板文本 1156 字。

    `mainframe`），`sniffReqLogType` 只比了下划线 `main_frame`，
    主文档一直被归成「其他」；详情文本查 `content-type` 是大小写敏感，
    而本地测试服务回的是 `Content-Type`。
  - 修（产品）：`sniffReqLogType` 同时认 `mainframe` / `subframe`
    与下划线形式；测试里详情检查对 `content-type` 不分大小写。
  - 第 5、6、7 遍：统一嗅探组与一键发布组全部 true；第 6 遍
    444 true / 50 false，第 7 遍复核同样 444 true / 50 false，
    唯一 false 的新增项是上面那项 mail.tm 网络波动。
