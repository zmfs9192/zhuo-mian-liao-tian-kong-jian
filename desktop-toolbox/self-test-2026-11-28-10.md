## 1. 实现位置

### 第 1 项 — IP 纯净度 4 家全败（根因在 Node 的 socket 复用上，修了三层）

- 现象：ipinfo.io、ipwho.is、ip.sb 三家 HTTPS 报 `WRONG_VERSION_NUMBER`（TLS 握手失败），ip-api.com（HTTP）报空消息 AggregateError。失败文案“IP 信息服务无响应”在误导人——握手失败不是服务无响应。
- 初查（两个 bug，实测复现）：`fetchText` 的代理分支（`main.js`）传 socket 时，HTTP 不传 hostname/port 会让 `http.request` 忽略 socket、改连默认 localhost:80（`/tmp/sock-test.js`、`/tmp/sock-test2.js` 复现）；HTTPS 用 `tls.connect({socket})` 再交 `https.request` 会双层 TLS，内层 ClientHello 被当应用数据，服务器回明文、内层握手报 WRONG_VERSION_NUMBER（`/tmp/tls-sock-test.js` 复现）。另 `pioneerProbeDetector` 缺 `tls` 分支，握手失败被误报成“检测服务访问失败”。
- **决定性实验（run 5 后）**：原始探针返回 `rawProbeText = 'HTTP/1.1 200 Connection Established\r\n\r\nHTTP/1.1 503 Service Unavailable\r\nContent-Length: 0\r\n\r\n'`——503 确实到了客户端，隧道与节点都没问题。区分实验（`/tmp/sock-use-test.js`）证明：**`http.request({socket, hostname, port})` 直接忽略 socket、直连目标**（目标命中 1 次，代理收到 0 字节）——即第一遍“补 hostname/port”的修法是错的，它让代理请求静默改走直连，run 2–5 里环回组“经隧道通”全是直连假象。进一步实验：`createConnection` 交已连 socket 时 HTTP 能走 socket、HTTPS 握手挂起（Agent 等已触发过的 connect 事件，`/tmp/sock-use-test4.js` 超时、ClientHello 未到代理）；`agent:false` 也一样（HTTP 照样直连，HTTPS 照样双层 TLS，`/tmp/sock-use-test5.js`）。**结论：此 Node 版本下没有办法让 http.request/https.request 使用预连的 CONNECT socket；唯一可靠的是探针的做法——手动写 HTTP、手动解析响应。**
- 最终修复（`main.js` `fetchText`）：`doReq` 改为纯直连（去掉 socket 参数）；新增 `doManualHttp(transport)`：在 socket（HTTPS 先 `tls.connect`）上手动写 HTTP 请求、手动解析响应（状态行、头、Content-Length / chunked / 读到关闭、重定向最多 5 次、网络闪断重试一次、超时、shouldStop、onChunk、maxBytes 上限），契约与 `doReq` 一致；CONNECT 响应按 Buffer 累积 + `sock.unshift` 推回多余字节（垃圾节点 HTTP 503 丢失的根因是 200 响应后多余字节被 `buf` 字符串累积吞掉）。所有错误分支补 `errorCategory`（`classifyNetError`：tls-handshake/dns/connect/proxy-refused/http/parse/unknown）。`pioneerProbeDetector` 同样补 `tls` 分支 + unshift。`pioneerFetchExitIp` 最坏情况优先选 `lastTls`。`pioneerFetchIpMeta` 按分类报错，全败文案改成“均失败（每家：分类（ms））”+ TLS 提示 + “点‘重新检测’再试一次” + 直连备选项说明；新增 IPC `pioneer-ip-purity-direct`（直连、不进缓存、标 direct）。**约束兑现：代理路径永远走 tunnel socket，绝不静默直连；直连只能是用户明确点的备选项，结果标“直连 IP（非代理出口）”。**
- 同 bug 扩散修复：`httpJsonOnce`（全工具箱 JSON 请求总入口：智能体 API、GitHub API、更新检查）与 `multipartPost`（改图）是同一手写 CONNECT + socket 模式，已一并改走 `fetchText`。`doManualHttp` 跳过调用方自带的 `Content-Length`（按 body 重算，免重复头）。`proxyTest` 是探针写法，没问题，不动。
- 自测组 `classifyNetError20261128`（WRONG_VERSION_NUMBER → tls-handshake、ECONNREFUSED → connect、ENOTFOUND → dns、HTTP 503 → http 等）、`tunnelLoopback20261128`（环回 Trojan 隧道：HTTPS/HTTP 经隧道真通、垃圾节点 HTTPS 报 WRONG_VERSION_NUMBER 且分类 tls-handshake、垃圾 HTTP 拿 503、死节点分类、节点 A/B 命中计数证明请求确实走了隧道）、`purityDirect20261128`（直连分支标 direct、不进缓存、错误带分类）。

## 3. 本轮修掉的真 bug（按实测）

1. **fetchText 代理路径根本没走隧道**：`http.request({socket})` 不传 hostname/port 时改连 localhost:80；补 hostname/port 后又直接忽略 socket、直连目标（静默改走直连）。此 Node 版本下没有办法让 http.request/https.request 使用预连的 CONNECT socket；`https.request` + `tls.connect({socket})` 会双层 TLS。修法：代理路径改手动写 HTTP、手动解析响应（`doManualHttp`）。**这是本轮最严重的 bug——它让 -17 之前所有经 Pioneer 代理的 HTTPS 请求（纯净度、智能体 API、更新检查、GitHub API）要么失败、要么静默直连。**
2. **httpJsonOnce / multipartPost 同 bug**：全工具箱 JSON 请求总入口与改图接口是同一手写 CONNECT + socket 模式，一并改走 `fetchText`。
3. **垃圾节点 HTTP 503 丢失**：200 响应后多余字节被 `buf` 字符串累积吞掉，CONNECT 响应改按 Buffer 累积 + `sock.unshift` 推回。
4. **代理规则被 Chromium 忽略**：`socks5=127.0.0.1:19352;http=127.0.0.1:19352` 下 HTTPS 解析为 DIRECT；单条 `socks5=` 两边都 DIRECT。全局/Tun 模式下内嵌浏览器的 HTTPS 从没进过隧道。修法：`http=…;https=…` 与 `socks5://host:port`。
5. **嗅探页签点不了**（-17 回归）：`renderSniffPanel` 每次 `innerHTML` 重建页签按钮，mousedown 与 mouseup 之间节点被销毁，click 永远触发不了。修法：就地更新 + 容器委托。
6. **手机远程 2 分钟后归 0**：PWA 无心跳，`lastSeenAt` 只在配对与鉴权时刷新。修法：60 秒心跳 + 在线窗口 180000ms。
7. **脱敏/文案类**：`pioneerFetchIpMeta` 全败文案“均无响应”误导人（握手失败 ≠ 服务无响应），改按分类报错。
