# 自测记录 2026-11-27-8：Pioneer 接管 Windows 系统代理

环境：Ubuntu 沙盒，Electron 38.8.6，Xvfb :99。

## 改了什么

- `setWindowsSystemProxy`（新增）：连接 Pioneer 后同时写 Windows 系统代理
  （HKCU `Internet Settings`，当前用户级，不用管理员权限）——全局/Tun
  走固定代理 `127.0.0.1:19352`，智能写 `data/pioneer-smart.pac` 并设
  AutoConfigURL；`pioneerApplyBrowserProxy` 同时接管内嵌浏览器会话与
  无自有代理的账号分区；断开时 `pioneerResetBrowserProxy` 一并复位。
- 复位按接管前保存的旧值恢复（`data/pioneer-prev-proxy.json`，只在首次
  接管时保存一次），不是简单关掉；没有保存过才关代理、删自动配置。
- 退出时同步写注册表（`pioneerResetSystemProxySync`，接在 before-quit
  里），保证进程退出前复位已落盘；启动时清理上次崩溃残留的接管
  （`pioneerCleanupStaleSystemProxy`，只清指向本地 19352 或我们 PAC
  的那一种，用户自己设的代理不动）。
- 补丁脚本里把 `pioneerEgressProxy()` 改成 `return null` 的那一行没有采纳：
  它是连 Trojan 节点用的上游出口代理（读环境变量 HTTP_PROXY），改掉后
  在公司内网等环境下节点根本连不上。
- 界面：代理页加了一行说明（连接后接管系统代理，断开或退出时恢复原来
  的设置）；`AGENTS.md` 新增第 11 节。

## 自测（`electron . --self-test`，真跑了一遍）

- 结果文件版本 2026.11.27-8；新增 `sysProxy20261127` 组 9/9 通过：
  全局设 ProxyServer、ProxyEnable=1、删 AutoConfigURL；智能设
  AutoConfigURL、ProxyEnable=0；按旧值恢复（重写回 ProxyServer、删
  AutoConfigURL）；无旧值时关代理；非 Windows 上接管/复位是空操作。
- 其余 false 项全部是已知 Linux 负项（Tun、winget、翻译插件、备份加密、
  更新检查等 Windows 专属或需真密钥的功能），与 -27-6 同类，没有新增
  失败项。
- exit 1 + SIGKILL 是已知的自测收尾方式，不是失败。

## 未验证（需真 Windows）

- 注册表实际写入与恢复（HKCU）、PAC 文件 + AutoConfigURL 在真实
  Edge/Chrome 里是否生效、断开与退出后原来代理是否原样回来、
  崩溃残留清理、真实 Pioneer 隧道起来后整机流量是否走代理。
- 特别说明：这版修的是“隧道通了以后代理接不接得到整机”；如果隧道本身
  一直连不上（登录、节点失效），问题在隧道那一步，不在这版的改动里。
